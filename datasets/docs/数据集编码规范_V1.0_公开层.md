# SINOSFT 数据集编码规范 V1.0（公开层）

> **版本**：V1.0-r1 · **编制日期**：2026-11-22
> **适用对象**：数据资产登记包、开源仿真协作包、技术白皮书数据集体系分册
> **定位**：定义数据资产层的编码结构与验证纪律；不替代构件层唯一身份编码体系。
> **边界**：本规范只描述公开层结构，不含可制造实现层参数。

---

## 一、编码层次总览

数据集体系采用七层编码，层层可追溯、层层可验证：

| 层次 | 编码对象 | 格式 | 示例 |
|---|---|---|---|
| L1 数据集码 | 一套独立登记数据 | `DS-<域>-<序号>` | `DS-SFT-EVAC-02` |
| L2 实体码 | 一类业务实体 | `SFT_<域>_<实体>` | `SFT_THERMAL_STORE` |
| L3 字段码 | 实体内字段 | `<实体>.<字段>` | `SFT_THERMAL_STORE.thermal_store_grade` |
| L4 规则码 | 硬约束 | `R-SFT-<域>-NN` | `R-SFT-EN-09` |
| L5 判定码 | 布尔决策标记 | 小写下划线命名 | `net_available_power_valid` |
| L6 案例码 | 仿真矩阵单条记录 | `<域>-SIM-<摘要10位>` | `EN-SIM-A1B2C3D4E5` |
| L7 包码 | 数据集封装 | `<数据集名>_数据集包.zip` + 指纹清单 | 见第七章 |

**总原则**：一件一码、一码一义、一义一验。任何一层出现重复、空值或无法追溯，
终检脚本必须将其判定为失败，不得人工放行。

---

## 二、L1 数据集码

### 2.1 格式定义

```
DS-<域缩写>-<两位序号>
```

- `DS` 为数据集层固定前缀；
- 域缩写采用大写 ASCII 字母与连字符，长度不超过 12；
- 序号按登记时间递增，一经分配不得复用、不得重排。

### 2.2 已分配清单

| 数据集码 | 技术域 | 登记申请号 | 状态 |
|---|---|---|---|
| `DS-SFT-VENT-01` | 通风导光消防 | 粤2026112206590 | 已保存，待提交 |
| `DS-SFT-EVAC-02` | 海面浮升疏散救生 | 粤2026112206591 | 已保存，待提交 |
| `DS-SHOP-ENERGY-03` | 海洋家园工程能源 | 粤2026112206592 | 已保存，待提交 |
| `DS-SEDIMENT-04` | 清淤与坝基 | 粤2026112206588 | 已提交，待审核 |

> 申请号是平台登记凭据，不是数据集码；两者一一绑定但不可互相替代。

### 2.3 域缩写分配表

| 缩写 | 含义 |
|---|---|
| `SFT-VENT` | 悬浮隧道通风导光消防 |
| `SFT-EVAC` | 海面浮升疏散救生 |
| `SHOP-ENERGY` | 海洋家园工程能源 |
| `SEDIMENT` | 清淤、坝基加固与下游减淤 |

新增域须先登记缩写，再分配序号；禁止先建数据后补码。

## 三、L2 实体码与 L3 字段码

### 3.1 实体码规则

```
SFT_<业务域>_<实体名>
```

- 全部大写 ASCII 字母与下划线；
- 业务域标识实体归属，实体名标识功能；
- 实体主键字段统一命名为 `<实体小写>_id`；
- 实体之间以外键关联，外键名指向被引用实体的主键。

示例实体：`SFT_ENERGY_PLATFORM`、`SFT_TIDAL_SIPHON`、`SFT_THERMAL_STORE`、
`SFT_EVAC_STAIR`、`SFT_LIFE_CABIN`、`SFT_LOAD_CANCELLATION_HARVEST`。

### 3.2 字段码规则

字段在包内以 Snake_case 命名；中文语义在字段字典中逐条登记，
字段码由「实体码.字段名」构成，全局唯一。

字段类型限定为以下枚举，不得自造类型：

| 类型 | 含义 | 约束 |
|---|---|---|
| `字符串(PK)` | 主键 | 非空、唯一 |
| `字符串(FK)` | 外键 | 必须命中被引用主键 |
| `字符串` | 文本标识 | 非空或按字典声明 |
| `枚举` | 档位取值 | 只能取字典声明的档位 |
| `布尔` | 二元标记 | 矩阵中以「成立 / 不成立」表达 |

### 3.3 字段值域纪律

- 枚举档位必须使用中文完整词，不得使用缩写或布尔替代；
- 布尔字段在字典中可写「布尔」，在矩阵中统一写「成立 / 不成立」；
- 结论字段统一写「通过 / 受限」；
- 任何字段不得承载可制造实现参数，违反者由公开层扫描拦截。

## 四、L4 规则码

### 4.1 格式定义

```
R-SFT-<域>-NN
```

`NN` 为两位序号，从 01 起连续编号，不得跳号、不得复用。
规则码一经发布只增不改：规则调整须新增修订版并保留原码历史。

### 4.2 已使用前缀

| 前缀 | 对应数据集 | 条数 |
|---|---|---:|
| `R-SFT-` | 通风导光消防（历史编号，保留原样） | 15 |
| `R-SFT-EVAC-` | 疏散救生 | 8 |
| `R-SFT-EN-` | 工程能源（含储能补充规则） | 9 |
| `R1` ~ `R18` | 清淤与坝基（历史编号，保留原样） | 18 |

**历史兼容原则**：已登记数据包中的规则编号格式一律保留，不因本规范发布而改名；
新设技术域统一采用 `R-SFT-<域>-NN` 格式。历史格式与新格式可以并存，
但同一数据包内不得混用两种格式。

### 4.3 规则记录必填项

每条规则至少包含：规则编号、规则内容、作用实体、密级标记。
规则内容须能被档位化判定引擎直接解释，禁止出现无法复算的形容词。

## 五、L5 判定码

布尔判定采用小写 Snake_case，统一以 `_valid`、`_pass`、`_flag` 结尾：

| 后缀 | 语义 |
|---|---|
| `_valid` | 综合有效性判定，通常由多条件联合成立 |
| `_pass` | 单项约束通过判定 |
| `_flag` | 状态标记或前置条件标记 |

判定码必须配套四项元数据：中文含义、成立条件、规则锚点串、输出示例。
判定为「通过」当且仅当该域全部判定同时成立；否则记「受限」并保留命中锚点。

## 六、L6 案例码

### 6.1 生成方式

案例码由该条记录全部输入档位拼接后取摘要生成：

```
<域缩写>-SIM-<摘要前10位大写>
```

摘要算法固定，输入顺序固定为字段字典声明顺序。
同一输入必得同一案例码；不同输入不得碰撞。

### 6.2 唯一性断言

终检脚本必须校验三项：

1. 案例码集合长度等于矩阵记录数；
2. 案例码无重复；
3. 随机复算任意记录，得到的案例码与记录一致。

任一项失败即判定矩阵不可信，禁止发布。

## 七、L7 包码与指纹清单

### 7.1 封装命名

```
<数据集正式名称>_数据集包.zip
```

正式名称以平台登记为准，一经生成不得随版本随意改名。
增补内容另建独立包，不覆盖原包、不改变原申请号。

### 7.2 指纹清单

每个数据包必须附带 `MANIFEST_<域>.csv`，逐件记录：

| 列 | 内容 |
|---|---|
| 相对路径 | 包内路径，统一正斜杠 |
| 字节 | 文件字节数 |
| SHA-256 | 文件摘要 |

终检须逐件重算并断言与清单全等；任一不符即失败。

### 7.3 审核摘录

当平台单附件体积受限时，允许上传确定性抽样的审核摘录，
但必须满足：抽样规则写入生成脚本、完整矩阵保留在数据包内、
摘录中保留全部「通过」样本。摘录不单独授权，不替代完整包。

## 八、版本管理

### 8.1 版本号

```
<主版本>.<修订版>-r<序号>
```

- 主版本：判定逻辑或实体结构发生不兼容变化；
- 修订版：新增字段、规则或说明，保持向下兼容；
- 修订序号：每次发布递增。

### 8.2 历史保留铁律

- 升级一律新建修订版文件，旧版归档、绝不覆盖或删除；
- 已生成的申请号、数据包、指纹清单与签字件不因文档升级而改写；
- 增补包与母包分开存证，各自保留独立指纹。

### 8.3 变更记录

每次修订须留四项：变更原因、影响范围、新增编码清单、回退方式。
变更记录随包归档，不写入公开摘要。

---

## 九、与构件编码体系的衔接

- 构件层唯一身份仍由既有编码纲要与数字资产编码体系管理；
- 本规范定义的是数据资产层编码，二者通过实体主键与数据集码建立映射；
- 数据集码不占用构件码空间，构件码不进入数据集字段字典；
- 任何声称「数据集码等同构件身份」的映射一律无效。

---

## 十、验证纪律

1. **脚本判定**：所有结论由脚本退出码判定，禁止手写通过。
2. **全量终检**：条目数、实体数、规则连续性、矩阵规模、列结构、
   取值合法性、综合判定一致性、字数约束、指纹一致性逐项断言。
3. **负注入**：故意注入错误样本，检测器必须捕获；未捕获即终检失败。
4. **密级扫描**：公开层扫描命中任何受控关键词即禁止发布。
5. **复现性**：第三方仅凭包内引擎与规则集即可重算矩阵，不依赖外部环境。

---

## 十一、密级标记

| 标记 | 含义 | 可发布范围 |
|---|---|---|
| 公开层 | 结构、字段、规则、档位、判定逻辑与统计结论 | 可入登记包与公开文档 |
| 受控层 | 可制造实现参数、内控原理与固定数值 | 不入公开层，按技术秘密管理 |

每份公开文档与数据包须带边界声明；受控内容不得以任何形式写入
公开文档、提交信息、日志或发布说明。

---

## 十二、附则

本规范自发布之日起施行。新增数据集、规则码、实体码须先在本规范登记，
再进入数据包生成流程。规范自身修订遵循第八章历史保留铁律。

共建共享，有边界亦有坦诚；可复核，亦可追溯。
